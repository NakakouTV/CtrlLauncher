# CtrlLauncher アーキテクチャ

## フォルダーの責務

| フォルダー | 内容 |
|---|---|
| `Models` | JSONへ保存するゲーム情報と難易度 |
| `ViewModels` | 画面状態、コマンド、ゲーム実行中の時間管理 |
| `Views` | ゲーム登録・編集画面のXAML |
| `Services` | JSON、パス、ログ、プロセス、ダイアログ、Win32デスクトップ |
| `Infrastructure` | `INotifyPropertyChanged` とコマンドの共通実装 |
| `Resources` | Visual StudioのXAMLデザイナーから編集できる色と共通スタイル |

外部MVVMライブラリやDIコンテナーは使っていません。依存関係は `App.xaml.cs` の起動処理にまとまっているため、初見でも生成順を追えます。

## 起動モード

通常起動ではタイトルバー付きウィンドウを表示します。これはVisual Studioからのデバッグ、ゲーム登録、展示準備に使います。

管理モードの「展示モード」は `DesktopSessionService` を呼び出します。このサービスは次の処理だけを担当します。

1. Win32 `CreateDesktop` で一時デスクトップを作る。
2. 同じランチャーを `--desktop-child` 付きでそのデスクトップへ起動する。
3. 名前付きイベントで、子プロセスの初回描画完了を待つ。
4. 15秒以内に準備できた場合だけ `SwitchDesktop` で表示を切り替える。子プロセスの終了・タイムアウト時は切り替えない。
5. 子プロセスの終了を待ち、`finally` で通常デスクトップへ戻して一時デスクトップのハンドルを閉じる。

子プロセスは全画面・枠なしで動作します。ゲームは子プロセスから起動するため、同じ一時デスクトップ上に表示されます。ゲーム実行中はランチャーウィンドウ自体を非表示にするため、背景をクリックしてもゲーム選択画面が前面には出ません。ゲーム終了時と交代案内時だけランチャーを再表示します。展示中の `Alt+F4` は無視し、管理モードの「終了」で通常デスクトップへ戻ります。Windowsのシャットダウンとログオフは妨げません。

展示用子プロセスでは、メインウィンドウ単位でWPFとWin32のIMEコンテキストを無効化し、TSFのフローティング言語バーも子プロセスの存続中だけ非表示にします。管理モードへの移行は低レベルキーボードフックでIMEより先に `C`、`T`、`R`、`L` の物理キー列を受け取り、対象キーを後続処理へ渡しません。

同じキーボードフックで展示中の `Alt+Tab` を抑止します。ゲーム実行中の場合はゲームのプロセスツリーを終了し、通常のゲーム終了監視を通してランチャーを再表示します。フック内では時間のかかる処理をせず、終了要求をWPF Dispatcherへ渡します。ウィンドウ終了時にはフックを必ず解除します。

これは強固なセキュリティ境界ではありません。実際に使う各PC・各ゲームで、通常デスクトップへの復帰、ゲーム異常終了、スリープ復帰を事前確認してください。

## JSON形式

```json
{
  "Title": "ゲーム名",
  "Genre": "ジャンル",
  "Description": "説明",
  "ExecutablePath": "Game.exe",
  "ScreenshotPath": "screenshot.png",
  "MinDifficulty": "Easy",
  "MaxDifficulty": "Hard"
}
```

難易度は `Default`、`Easy`、`Normal`、`Hard` の文字列で保存します。難易度表示を無効にすると両方を `Default` にします。

ゲーム名は表示タイトルとフォルダー名を兼ねます。編集でゲーム名を変えた場合は `data/<旧名>` と、存在すれば `src/<旧名>` を改名します。保存や改名に失敗した場合は、移動済みフォルダーを可能な限り元の名前へ戻します。

## エラーとログ

日別ログを `logs/yyyy-MM-dd.log` に保存します。ゲーム設定1件のJSONが壊れていても、ほかのゲームは読み込みを継続します。UIスレッドの未処理例外もログへ記録します。

ゲーム削除は確認後、`data/<ゲーム名>` をWindowsのごみ箱へ移動します。ゲーム本体・画像・設定はすべてこのフォルダーに含まれます。
